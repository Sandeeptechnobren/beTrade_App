# lib/

## Purpose
Root of all Dart/Flutter source for the BeTrade mobile app. Boots once from `main.dart` and fans out into three layers: `core/` (cross-cutting infrastructure), `data/` (model + provider + services), and `presentation/` (UI). No business logic at this level — only the bootstrap.

## Key files
- `main.dart` — entry. `WidgetsFlutterBinding.ensureInitialized()` → `Firebase.initializeApp(...)` → `LocalStorage.init()` → `dotenv.load(".env")` → lock portrait → wrap app in `MultiProvider` (~14 `ChangeNotifier`s) + `ScreenUtilInit(393×852)` + `Consumer<ThemeProvider>` + `MaterialApp(home: SplashScreen())`. Registers the FCM background handler.
- `firebase_options.dart` — auto-generated by FlutterFire CLI. Two Firebase projects: `betrade-new` (Android/iOS) and `betrade-4efd1` (Web/macOS/Windows).
- `core/` — env config, Dio singleton, theme tokens, validators, animations.
- `data/model/` — ~13 manual-`fromJson` DTOs.
- `data/provider/` — ~14 `ChangeNotifier`s.
- `data/services/` — ~16 static API + storage services.
- `presentation/screens/` — ~20 feature screens + `main_screen.dart` IndexedStack host.
- `presentation/widget/` — 14 reusable widgets.

## Data flow
HTTP request: UI → `context.read<Provider>()` → static `Service.method()` → `DioClient.instance` (or legacy `http`) → backend at `api.buildacademy.io`. Response decoded via `Model.fromJson` → stored on provider → `notifyListeners()` → `Consumer` / `context.watch` rebuilds. Token persists in `SharedPreferences` via `LocalStorage`. Push notifications via FCM.

## Dependencies
- Outbound: Flutter SDK; `dio`, `http`, `provider`, `firebase_core`, `firebase_messaging`, `flutter_local_notifications`, `flutter_dotenv`, `shared_preferences`, `flutter_screenutil`, `fl_chart`, `iconsax`, `lucide_icons`, `pinput`, `camera`, `image_picker`, `permission_handler`, `path_provider`, `flutter_image_compress`.
- Inbound: `android/` and `ios/` build the Flutter module from here.

## Conventions
See `docs/PATTERNS.md` for the full style guide. In short: services = abstract classes with `static` methods; providers = `ChangeNotifier` with public mutable `isLoading`/`error`/data fields; models = hand-written (`fromJson` only, no `toJson`, no codegen); env via `EnvConfig.baseUrl`; URLs via `ApiEndpoints`. **~14 providers and ~13 models as of 2026-05-23 — earlier subdir docs said 9 / 5 (stale).** Prefer `dio` + `DioClient` over `http` in new code; the dual-client situation is documented cleanup work.

## Common commands
- `flutter pub get` — resolve dependencies.
- `flutter analyze` — static analysis (`analysis_options.yaml` includes `flutter_lints`).
- `flutter run` — run on connected device/emulator.
- `flutter test` — **currently fails on `main`** (see `test/CLAUDE.md`).
- `flutter build apk` / `appbundle` / `ios` / `ipa` — release artefacts.
